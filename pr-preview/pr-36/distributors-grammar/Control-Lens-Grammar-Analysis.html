Description

Static analyses of RegExtended Bnfs, as generated from context-free grammars by Control.Lens.Grammar.regbnfG, over any token.

A RegEx is the free KleeneStarAlgebra of token classes & nonterminals, so an analysis which composes, like nullability or the first tokens of a word, is the unique homomorphism out of it, foldRegEx, into another KleeneStarAlgebra, with a least fixpoint, fixRules, for the rules naming each other. An analysis which depends on context, like the tokens which may follow a rule, flows down from its callers, in follows. The LL(1) conflicts, ll1Conflicts, are built of them.

LL(1)

ll1Conflicts :: Categorized token => Bnf (RegEx token) -> [LL1Conflict token] Source #

The conflicts which keep a RegExtended Bnf from being LL(1), that is, from being parsed predictively by one token of lookahead, committing to an alternative by its first token, as tParsector does. An empty list means the grammar is LL(1).

Alternatives are tried in order, so besides the usual conditions, that alternatives start with distinct tokens & that repetitions & options start with tokens which can't follow them, a nullable alternative mustn't precede one which can consume tokens, since it would succeed first, without consuming them. Left recursion is reported too, since a predictive parser diverges on it. A conflict which a try resolves isn't reported: of alternatives, the first of which backtracks, or of a repetition which backtracks, since a predictive parser then tries what follows anew.

>>> map conflictSort (ll1Conflicts ("{start} = ab|ac" :: Bnf (RegEx Char)))
[LL1FirstFirst]
>>> ll1Conflicts ("{start} = ab|c" :: Bnf (RegEx Char))
[]

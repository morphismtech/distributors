Regular grammar

A regular grammar may be constructed using terminal symbols, Tokenized combinators, tokenClasses and Alternator combinators. Let's see an example using semantic versioning syntax.

>>> import Numeric.Natural (Natural)
>>> :{
data SemVer = SemVer          -- e.g., 2.1.5-rc.1+build.123
  { major         :: Natural  -- e.g., 1
  , minor         :: Natural  -- e.g., 2
  , patch         :: Natural  -- e.g., 3
  , preRelease    :: [String] -- e.g., "alpha.1", "rc.2"
  , buildMetadata :: [String] -- e.g., "build.123", "20130313144700"
  }
  deriving (Eq, Ord, Show, Read)
:}

We'd like to define an optic _SemVer, corresponding to the constructor pattern SemVer. You could generate it with the TemplateHaskell combinator, makeNestedPrisms.

makeNestedPrisms ''SemVer

Unfortunately, we can't use TemplateHaskell to generate it in GHCi, which is used to test this documentation. Here is equivalent Haskell code instead. Since SemVer has only one constructor, _SemVer can be an Iso.

>>> :set -XRecordWildCards
>>> import Control.Lens (Iso', iso)
>>> :{
_SemVer :: Iso' SemVer (Natural, (Natural, (Natural, ([String], [String]))))
_SemVer = iso
  (\SemVer {..} -> (major, (minor, (patch, (preRelease, buildMetadata)))))
  (\(major, (minor, (patch, (preRelease, buildMetadata)))) -> SemVer {..})
:}

Now we can build a RegGrammar for SemVer using the "idiom" style of Applicative parsing with a couple modifications.

>>> :{
semverGrammar :: RegGrammatical Char p => p SemVer SemVer
semverGrammar = _SemVer
  >?  numberG
  >*< terminal "." >* numberG
  >*< terminal "." >* numberG
  >*< optionP _Empty (terminal "-" >* identifiersG)
  >*< optionP _Empty (terminal "+" >* identifiersG)
  where
    numberG = numeral 10
    identifiersG = sepWith "." (atLeast 1) (someP charG)
    charG = asIn LowercaseLetter
      >|< asIn UppercaseLetter
      >|< asIn DecimalNumber
      >|< token '-'
instance CtxGrammar Char SemVer
instance Grammar Char SemVer
instance RegGrammar Char SemVer where regGrammar = semverGrammar
:}

A type's RegGrammar instance, here semverGrammar, & its Grammar & CtxGrammar instances, by default, let generators run it by its type, a required type argument, (type SemVer) where a constructor shares its name, & parsers & printers by inference.

Instead of using the constructor SemVer with the Functor applicator <$>, we use the optic _SemVer we defined and the Choice applicator >?; although, we could have used the Profunctor applicator >~ instead, because _SemVer is an Iso.

You can generate a regular expression string, a RegEx, from a RegGrammar with regexG.

>>> putStringLn (regexG (type SemVer))
[0-9]+.[0-9]+.[0-9]+(-(\p{Ll}|\p{Lu}|\p{Nd}|-)+(.(\p{Ll}|\p{Lu}|\p{Nd}|-)+)*)?(\+(\p{Ll}|\p{Lu}|\p{Nd}|-)+(.(\p{Ll}|\p{Lu}|\p{Nd}|-)+)*)?

You can also generate parsers and printers.

>>> [parsed | (parsed, "") <- parseG @SemVer "2.1.5-rc.1+build.123"]
[SemVer {major = 2, minor = 1, patch = 5, preRelease = ["rc","1"], buildMetadata = ["build","123"]}]

Parsing unconses tokens left-to-right, from the beginning of a string. Unparsing, on the other hand, snocs tokens left-to-right, to the end of a string.

>>> unparseG (SemVer 1 0 0 ["alpha"] []) "SemVer: " :: Maybe String
Just "SemVer: 1.0.0-alpha"

Printing, on the gripping hand, conses tokens right-to-left, to the beginning of a string.

>>> ($ " is the SemVer.") <$> printG (SemVer 1 2 3 [] []) :: Maybe String
Just "1.2.3 is the SemVer."

Profunctorial combinators give us correct-by-construction invertible parsers. New RegGrammar generators can be defined with new RegGrammatical instances.

regexG generates a RegExpression from a regular grammar, over any token, a regular expression string over characters. Since context-free Grammars and CtxGrammars aren't necessarily regular, the type system will prevent regexG from being applied to them.

Context-free grammar

Context-free Grammars add two capabilities to RegGrammars, coming from the BackusNaurForm interface

  • rule abstraction,
  • and general recursion.

The Grammars of RegExpressions & of their Bnfs, in Control.Lens.Grammar.RegEx, are examples of context-free Grammars. Regular expressions are a form of expression algebra. Let's see a similar but simpler example, the algebra of arithmetic expressions of natural numbers.

>>> import Numeric.Natural (Natural)
>>> :{
data Arith
  = Num Natural
  | Add Arith Arith
  | Mul Arith Arith
  deriving stock (Eq, Ord, Show, Read)
:}

Here are Prisms for the constructor patterns.

>>> import Control.Lens (Prism', prism')
>>> :{
_Num :: Prism' Arith Natural
_Num = prism' Num (\case Num n -> Just n; _ -> Nothing)
_Add, _Mul :: Prism' Arith (Arith, Arith)
_Add = prism' (uncurry Add) (\case Add x y -> Just (x,y); _ -> Nothing)
_Mul = prism' (uncurry Mul) (\case Mul x y -> Just (x,y); _ -> Nothing)
:}

Now we can build a Grammar for Arith by combining "idiom" style with named rules, and tying the recursive loop (caused by parenthesization) with ruleRec.

>>> :{
arithGrammar :: Grammatical Char p => p Arith Arith
arithGrammar = ruleRec "arith" sumG
  where
    sumG arith = rule "sum" $
      sepWith "+" (chain1 Left _Add) (prodG arith)
    prodG arith = rule "product" $
      sepWith "*" (chain1 Left _Mul) (factorG arith)
    factorG arith = rule "factor" $
      numberG >|< terminal "(" >* arith *< terminal ")"
    numberG = rule "number" $
      _Num >? numeral 10
instance CtxGrammar Char Arith
instance Grammar Char Arith where grammar = arithGrammar
:}

We can generate grammar strings, printers and parsers from arithGrammar.

>>> putStringLn (regbnfG Arith)
{start} = \q{arith}
{arith} = \q{sum}
{factor} = \q{number}|\(\q{arith}\)
{number} = [0-9]+
{product} = \q{factor}(\*\q{factor})*
{sum} = \q{product}(\+\q{product})*
>>> [x | (x,"") <- parseG @Arith "1+2*3+4"]
[Add (Add (Num 1) (Mul (Num 2) (Num 3))) (Num 4)]
>>> unparseG (Add (Num 1) (Mul (Num 2) (Num 3))) "" :: Maybe String
Just "1+2*3"
>>> do pr <- printG (Num 69); pure (pr "") :: Maybe String
Just "69"

Operator tables with precedence, like buildExpressionParser's, are built by withOperators. For example, an expression grammar over natural numbers with a postfix factorial ! (binding tightest, and not required to actually compute a factorial), a right-associative exponent ^, a left-associative *, and left-associative + & - binding loosest:

>>> :{
data Expr
  = Nat Natural
  | Fac Expr
  | Exp Expr Expr
  | Mul Expr Expr
  | Add Expr Expr
  | Sub Expr Expr
  deriving stock (Eq, Ord, Show, Read)
_Nat :: Prism' Expr Natural
_Nat = prism' Nat (\case Nat n -> Just n; _ -> Nothing)
_Fac :: Prism' Expr Expr
_Fac = prism' Fac (\case Fac x -> Just x; _ -> Nothing)
_Exp, _Mul, _Add, _Sub :: Prism' Expr (Expr, Expr)
_Exp = prism' (uncurry Exp) (\case Exp x y -> Just (x,y); _ -> Nothing)
_Mul = prism' (uncurry Mul) (\case Mul x y -> Just (x,y); _ -> Nothing)
_Add = prism' (uncurry Add) (\case Add x y -> Just (x,y); _ -> Nothing)
_Sub = prism' (uncurry Sub) (\case Sub x y -> Just (x,y); _ -> Nothing)
exprGrammar :: Grammatical Char p => p Expr Expr
exprGrammar = ruleRec "expr" $ \expr ->
  let atom = rule "atom" $ nat >|< terminal "(" >* expr *< terminal ")"
      nat  = rule "nat"  $ _Nat >? numeral 10
  in withOperators
    [ [ Postfix _Fac (terminal "!") ]
    , [ Infix RightAssoc _Exp (terminal "^") ]
    , [ Infix LeftAssoc _Mul (terminal "*") ]
    , [ Infix LeftAssoc _Add (terminal "+"), Infix LeftAssoc _Sub (terminal "-") ]
    ] atom
instance CtxGrammar Char Expr
instance Grammar Char Expr where grammar = exprGrammar
:}

The right-associative ^ groups to the right, - to the left, * binds tighter than +, and postfix ! binds tighter than ^:

>>> [e | (e,"") <- parseG @Expr "2^3^2"]
[Exp (Nat 2) (Exp (Nat 3) (Nat 2))]
>>> [e | (e,"") <- parseG @Expr "3-2-1"]
[Sub (Sub (Nat 3) (Nat 2)) (Nat 1)]
>>> [e | (e,"") <- parseG @Expr "2*3+4"]
[Add (Mul (Nat 2) (Nat 3)) (Nat 4)]
>>> [e | (e,"") <- parseG @Expr "2*(3+4)"]
[Mul (Nat 2) (Add (Nat 3) (Nat 4))]
>>> [e | (e,"") <- parseG @Expr "3!"]
[Fac (Nat 3)]
>>> [e | (e,"") <- parseG @Expr "2^3!"]
[Exp (Nat 2) (Fac (Nat 3))]

Being bidirectional, the same grammar prints:

>>> unparseG (Exp (Nat 2) (Exp (Nat 3) (Nat 2))) "" :: Maybe String
Just "2^3^2"
>>> unparseG (Exp (Nat 2) (Fac (Nat 3))) "" :: Maybe String
Just "2^3!"

If all rules are non-recursive, then a Grammar can be rewritten as a RegGrammar. Since Haskell permits general recursion, and RegGrammars are embedded in Haskell, you can define context-free grammars with them. But it's recommended to use Grammars for rule abstraction and generator support for ruleRec.

Grammar Char (Bnf (RegEx Char)) Source #

The context-free Grammar of Bnfs of RegExpressions of characters, by which they're IsString & IsList. That means that it can generate a self-hosted definition.

Bnfs of RegExpressions of characters are an embedded domain specific language of Backus-Naur forms extended by regular expression strings.

Such a Bnf consists of a distinguished "start" RegEx, and a set of named RegEx rules.

>>> putStringLn (rule "baz" (terminal "foo" >|< terminal "bar") :: Bnf (RegEx Char))
{start} = \q{baz}
{baz} = foo|bar

Like RegExpressions, they have a string-like interface.

>>> let bnf = fromString "{start} = foo|bar" :: Bnf (RegEx Char)
>>> putStringLn bnf
{start} = foo|bar
>>> toList bnf
"{start} = foo|bar"
>>> :type toList bnf
toList bnf :: [Char]

They can be generated from context-free Control.Lens.Grammar.Grammars with Control.Lens.Grammar.regbnfG.

Like RegExpressions, they can be constructed using terminal, Tokenized, Monoid and KleeneStarAlgebra combinators. But they also support BackusNaurForm rules and ruleRecs.

>>> putStringLn (rule "baz" (bnf >|< terminal "baz"))
{start} = \q{baz}
{baz} = foo|bar|baz
>>> putStringLn (ruleRec "∞-loop" (\x -> x) :: Bnf (RegEx Char))
{start} = \q{∞-loop}
{∞-loop} = \q{∞-loop}

Grammar Char (RegEx Char) Source #

The context-free Grammar of RegExpressions of characters, in the syntax of regular expression strings, by which they're IsString & IsList. It can't be a Control.Lens.Grammar.RegGrammar, since regular expression strings include parenthesization. But balanceBy parentheses are a context-free language.

RegExpressions of characters are an embedded domain specific language of regular expression strings.

Since they are strings, they have a string-like interface.

>>> let rex = fromString "ab|c" :: RegEx Char
>>> putStringLn rex
ab|c
>>> toList rex
"ab|c"

They can be generated from Control.Lens.Grammar.RegGrammars with Control.Lens.Grammar.regexG.

>>> toList (runGrammor (terminal "a" >* terminal "b" >|< terminal "c") :: RegEx Char)
"ab|c"

A regular expression string is stored as an algebraic datatype, a RegEx.

>>> rex
RegExam (Alternate (Sequence (RegExam (OneOf (fromList "a"))) (RegExam (OneOf (fromList "b"))) []) (RegExam (OneOf (fromList "c"))) [])

They're similar to regular expression strings in many other programming languages. We can use them to see if a word and pattern are Matching.

>>> "ab" =~ rex
True
>>> "c" =~ rex
True
>>> "xyz" =~ rex
False

Like Control.Lens.Grammar.RegGrammars, they can use all the terminal & Tokenized combinators. Unlike Control.Lens.Grammar.RegGrammars, instead of using Monoidal and Alternator combinators, they use Monoid and KleeneStarAlgebra combinators.

>>> toList (terminal "a" <> terminal "b" >|< terminal "c" :: RegEx Char)
"ab|c"
>>> toList (mempty :: RegEx Char)
""

Since they're a KleeneStarAlgebra, they support Kleene quantifiers.

>>> toList (starK rex)
"(ab|c)*"
>>> toList (plusK rex)
"(ab|c)+"
>>> toList (optK rex)
"(ab|c)?"

Like other regular expression languages, they support character classes.

>>> toList (oneOf "abc" :: RegEx Char)
"[a-c]"
>>> toList (notOneOf "abc" :: RegEx Char)
"[^a-c]"

The character classes are used for failure, matching no character or string, as well as the wildcard, matching any single character.

>>> toList (falseP :: RegEx Char)
"[]"
>>> toList (anyToken :: RegEx Char)
"[^]"

Additional forms of character classes test for a character's GeneralCategory.

>>> toList (asIn LowercaseLetter :: RegEx Char)
"\\p{Ll}"
>>> toList (notAsIn Control :: RegEx Char)
"\\P{Cc}"

KleeneStarAlgebras support alternation >|<, and the Tokenized combinators are all negatable. However, we'd like to be able to take the intersection of character classes as well. they can combine characters' tokenClasses using BooleanAlgebra combinators.

>>> toList (tokenClass (notOneOf "abc" >&< notOneOf "xyz") :: RegEx Char)
"[^a-cx-z]"
>>> toList (tokenClass (oneOf "abcxyz" >&< notOneOf "xyz") :: RegEx Char)
"[a-c]"
>>> toList (tokenClass (notOneOf "#$%" >&< notAsIn Control) :: RegEx Char)
"[^#-%\\P{Cc}]"
>>> toList (tokenClass (allP notAsIn [MathSymbol, Control]) :: RegEx Char)
"\\P{Sm|Cc}"
>>> toList (tokenClass (notP (oneOf "xyz")) :: RegEx Char)
"[^x-z]"

Ill-formed regular expression strings normalize to failure.

>>> toList (fromString ")(" :: RegEx Char)
"[]"

Context-sensitive grammar

For context-sensitivity, the Monadic interface is used by importing Data.Profunctor.Monadic.Do qualified and using a "bonding" notation which mixes "idiom" style with qualified do-notation. Let's use length-encoded vectors of numbers as an example.

>>> import Numeric.Natural (Natural)
>>> import Control.Lens.Iso (Iso', iso)
>>> :set -XRecordWildCards
>>> :{
data LenVec = LenVec {length :: Natural, vector :: [Natural]}
  deriving (Eq, Ord, Show, Read)
_LenVec :: Iso' LenVec (Natural, [Natural])
_LenVec = iso (\LenVec {..} -> (length, vector)) (\(length, vector) -> LenVec {..})
:}

>>> :set -XQualifiedDo
>>> import qualified Data.Profunctor.Monadic.Do as P
>>> :{
lenvecGrammar :: CtxGrammatical Char p => p LenVec LenVec
lenvecGrammar = _LenVec >? P.do
  let
    numberG = numeral 10
    vectorG n = sepWith "," (exactly n) numberG
  len <- numberG             -- bonds to _LenVec
  terminal ";"               -- doesn't bond
  vectorG (fromIntegral len) -- bonds to _LenVec
instance CtxGrammar Char LenVec where ctxGrammar = lenvecGrammar
:}

The qualified do-notation changes the signature of P.>>=, so that we must apply the constructor pattern _LenVec to the do-block with the >? applicator. Any scoped bound action, var <- action, gets "bonded" to the constructor pattern. Unbound actions, except for the last action in the do-block, don't get bonded to the pattern. The last action does get bonded to the pattern. Any unscoped bound action, _ <- action, also gets bonded to the pattern, but being unscoped means it isn't added to the context. If all bound actions are unscoped, and filtration & failure handling aren't used, then a CtxGrammar can be rewritten as a Grammar since it is context-free. We can't generate a Bnf from a CtxGrammar since the rules aren't static, but dynamic and contextual. We can generate parsers and printers as expected.

>>> [vec | (vec, "") <- parseG "3;1,2,3"] :: [LenVec]
[LenVec {length = 3, vector = [1,2,3]}]
>>> [vec | (vec, "") <- parseG "0;1,2,3"] :: [LenVec]
[]
>>> [pr "" | pr <- printG (LenVec 2 [6,7])] :: [String]
["2;6,7"]
>>> [pr "" | pr <- printG (LenVec 200 [100])] :: [String]
[]

In addition to context-sensitivity via Monadic combinators, CtxGrammars add unrestricted filtration to Grammars. The satisfy combinator is an unrestricted token filter. And the satisfied pattern is used together with the Choice & Cochoice applicator >?< for unrestricted filtration.

>>> :{
palindromeG :: CtxGrammatical Char p => p String String
palindromeG = rule "palindrome" $
  satisfied (\wrd -> reverse wrd == wrd) >?< manyP (anyToken @Char)
:}

>>> [pal | word <- ["racecar", "word"], (pal, "") <- parseP (palindromeG :: Parsor String [] String String) word]
["racecar"]

Since CtxGrammars are embedded in Haskell, permitting computable predicates, and Filtrator has a default definition for Monadic Alternators, the context-sensitivity of CtxGrammar implies unrestricted filtration of grammars by computable predicates, which can recognize the larger class of recursively enumerable languages.

Context-sensitivity can also be optical. A Varifocal is an optic whose shape depends on the foci it builds, as no Bifocal can, applied in a CtxGrammar by contextually, or on a MonadicTrans profunctor, by contextuallyT. A heredoc's lines are its foci, its tag, its body, & its tag again, delimitBy by the first line equal to the opening tag, a language which isn't context-free.

>>> :{
data Heredoc = Heredoc String [String] deriving (Eq, Show)
heredocG :: CtxGrammatical Char p => p Heredoc Heredoc
heredocG = lined >~ terminal "<<" >* contextually (delimitBy (==)) lineG
  where
    lineG = manyP (notOneOf "\n") *< terminal "\n"
    lined = iso
      (\(Heredoc tag body) -> tag : body ++ [tag])
      (\case
        tag : rest -> Heredoc tag (if null rest then [] else init rest)
        [] -> Heredoc "" [])
instance CtxGrammar Char Heredoc where ctxGrammar = heredocG
:}

>>> [pr "" | pr <- printG (Heredoc "EOF" ["hi"])] :: [String]
["<<EOF\nhi\nEOF\n"]
>>> [h | (h, "") <- parseG @Heredoc "<<EOF\nhi\nEOF\n"]
[Heredoc "EOF" ["hi"]]
>>> parsecResult (parsecG @Heredoc "<<EOF\nhi\nEOF\n")
Just (Heredoc "EOF" ["hi"])
>>> [pr "" | pr <- printG (Heredoc "EOF" ["EOF"])] :: [String]
[]

Finally, CtxGrammars support failure reporting and backtracking. This has no effect on printG, parseG or unparseG; but it affects parsecG and unparsecG. For context, an LL grammar can be (un)parsed by an LL parser. An LL parser (un)parses from left to right, and constructs leftmost derivations. An LL(k) parser can look k tokens ahead. tParsor is an LL(∞) parser. tParsector is an LL(1) parser. The backtracking try combinator restores full lookahead to Parsector. Since both Parsor & Parsector are LL parsers they diverge if the CtxGrammar they're run on is left-recursive.

>>> parsecP (rule "foo" (fail "bar") >|< fail "baz") "abc"

>>> parsecP (manyP (token 'a') >*< asIn @Char DecimalNumber :: Parsector String (String, Char) (String, Char)) "aaab"

  deriving newtype
    ( Functor, Applicative, Alternative
    , Monad, MonadPlus, MonadFail

instance TerminalSymbol Char (WrapMega ()) where
  terminal str = WrapMega (M.chunk str *> pure ())
instance TokenAlgebra Char (WrapMega Char) where
  tokenClass exam = WrapMega $ M.label (show exam) (M.satisfy (tokenClass exam))

  anyToken = WrapMega M.anySingle
  token = WrapMega . M.single
  oneOf = WrapMega . M.oneOf
  notOneOf = WrapMega . M.noneOf
  asIn cat = WrapMega $ M.label ("in category " ++ show cat) (M.satisfy (asIn cat))

BackusNaurForm grammar combinators formalize traced rule abstraction and general recursion with ruleRec, related by this invariant.

prop> rule label bnf = ruleRec label (\_ -> bnf)

The BackusNaurForm interface is reminiscent of two distinct notions of "trace". First as a traced Cartesian monoidal category which models general recursion abstractly, and second as a trace-like label for rule abstraction. The category (->) already has a traced (,)-monoidal structure in the form of unfirst = loop or equivalently the fixpoint function fix, determining the default method for a BackusNaurForm, by which the invariant holds for any Ruled rule.

prop> ruleRec label = rule label . fix

The BackusNaurForm interface permits overloading these methods, and tracing them with a label.

Both context-free Grammars & CtxGrammars support the BackusNaurForm interface. See Breitner, Showcasing Applicative, for the original interface.

class Applicative f => Alternative (f :: Type -> Type) where #

A monoid on applicative functors.

If defined, some and many should be the least solutions of the equations:

  • some v = (:) <$> v <*> many v
  • many v = some v <|> pure []

Examples

Expand
>>> Nothing <|> Just 42
Just 42

>>> [1, 2] <|> [3, 4]
[1,2,3,4]

>>> empty <|> print (2^15)
32768

Minimal complete definition

empty, (<|>)

Examples

Expand

class Monad m => MonadFail (m :: Type -> Type) where #

When a value is bound in do-notation, the pattern on the left hand side of <- might not match. In this case, this class provides a function to recover.

A Monad without a MonadFail instance may only be used in conjunction with pattern that always match, such as newtypes, tuples, data types with only a single data constructor, and irrefutable patterns (~pat).

Instances of MonadFail should satisfy the following law: fail s should be a left zero for >>=,

fail s >>= f  =  fail s

If your Monad is also MonadPlus, a popular definition is

fail _ = mzero

fail s should be an action that runs in the monad itself, not an exception (except in instances of MonadIO). In particular, fail should not be implemented in terms of error.
